# 데이터셋 조사 및 적합성 검토

> 프로젝트: **밤마실** — 야맹증 저시력자의 야간 보행을 돕는 실시간 AI 시각보조 서비스
> 목적: 4단계 파이프라인(눈부심 억제 → 저조도 개선 → 위험 요소 탐지 → 선택적 강조) 학습에 필요한 공개 데이터셋 정리

## 프로젝트 데이터 요구사항

파이프라인 단계별로 필요한 학습 데이터가 다르다.

| 단계 | 필요 데이터 | 유형 |
|------|-------------|------|
| ② 저조도 개선(톤매핑) | 저조도 ↔ 정상조도 **쌍(paired)** 이미지 | 이미지 복원/향상 |
| ③ 위험 요소 탐지 | 야간·저조도 환경의 **계단·보행자** 등 객체 라벨(BBox) | 객체탐지 |

핵심 제약: **야간/저조도 + 보행(도로·인도) 시점 + 계단·보행자 클래스**. 자율주행(차량 시점) 데이터는 보행 시점과 화각·거리감이 달라 그대로 쓰기엔 한계가 있어 파인튜닝이 전제되어야 함.

## 1. 기획서 언급 데이터셋 적합성 검토

### NightOwls — ✅ 적합 (보행자 탐지 사전학습 핵심)
- **구성**: 40개 시퀀스 279k 프레임, 3개국(독일·네덜란드·영국) 야간 촬영, 계절·날씨 다양. 전 프레임 어노테이션(occlusion·pose·difficulty·tracking 포함).
- **클래스**: 보행자(pedestrian) 중심.
- **평가**: 야간 저조도·저대비·블러 환경의 **보행자 탐지**에 특화되어 프로젝트 목표(③ 위험 요소 탐지)에 정면 부합. 사전학습 → 자체 데이터 파인튜닝 구성에 이상적.
- **한계**: 차량 대시캠 시점이라 보행자 시점(eye-level)과 차이 존재. 계단 클래스 없음.
- 링크: https://www.nightowls-dataset.org/

### ExDark (Exclusively Dark) — ✅ 적합 (저조도 다중객체 사전학습)
- **구성**: 7,363장의 저조도 이미지, 10단계 조도(달빛~실내 약광). 12개 객체 클래스 BBox 라벨.
- **클래스**: 사람(people), 자전거, 자동차, 버스 등 12종. 계단은 없음.
- **평가**: 다양한 저조도 레벨의 **다중객체 탐지** 사전학습에 유용. 사람 클래스가 보행자 보조로 활용 가능. 저조도 개선 연구의 벤치마크로도 널리 쓰임.
- **한계**: 보행 전용이 아니라 일반 장면. 계단 미포함.
- 링크: https://github.com/cs-chan/Exclusively-Dark-Image-Dataset

> **결론**: 두 데이터셋 모두 프로젝트에 적합하며 기획서의 "사전학습" 단계 근거로 타당함. 다만 **계단 클래스 부재**와 **보행 시점 부족**이 공통 공백 → 아래 추가 데이터로 보완 필요.

## 2. 추가 추천 — 저조도 개선(②단계, paired 데이터)

②단계 톤매핑 학습에는 저조도↔정상 **쌍** 데이터가 필수인데, 위 탐지용 데이터셋은 쌍이 아니므로 별도 확보가 필요하다.

| 데이터셋 | 구성 | 적합성 | 비고 |
|----------|------|--------|------|
| **LOL (v1/v2)** | v1: 500쌍(실내 중심), v2-real: 789쌍(실내외) | ✅ 저조도 개선 표준 벤치마크 | 규모 작음, 실내 편중 |
| **LoLI-Street** | 33k쌍 + 실제 저조도 테스트 1,000장, **거리(street) 장면** | ✅✅ 야외 거리 장면으로 보행 시나리오에 근접 (2024) | 최신, 도심 특화. Kaggle·Google Drive 배포 |
| **LSRW** | 5,650쌍(실내외) — Nikon 3,170 + **화웨이 스마트폰 2,480**, 실사 쌍 | ✅✅ 내용상 적합(스마트폰 촬영 포함 → 타깃 기기와 근접)이나 **배포 경로 문제로 미사용** | ⛔ 아래 주석 참고 |
| **SID (See-in-the-Dark)** | 5,094쌍 RAW(단노출↔장노출) | △ 극저조도지만 RAW 기반 | 모바일 파이프라인엔 전처리 필요 |

> **⛔ LSRW 미사용 결정 (2026-07-26)**
> LSRW는 **데이터셋·사전학습 모델이 모두 Baidu Pan(百度网盘)으로만 배포**된다 (`pan.baidu.com/s/1XHWQAS0ZNrnCyZ-bq7MKvA`, 추출코드 `wmrr`). 공식 저장소 [JianghaiSCU/R2RNet](https://github.com/JianghaiSCU/R2RNet)에도 미러가 없다.
> Baidu Pan은 **중국 휴대폰 번호 기반 계정 가입**과 전용 클라이언트 설치가 사실상 강제되고, 미가입·무료 계정은 국내에서 전송 속도가 극히 낮아 수 GB 규모 취득이 현실적이지 않다. 계정 생성 자체가 개인정보 제공을 수반한다는 점도 부담.
> → **내용 적합성과 무관하게 취득 비용 문제로 사용하지 않는다.** 대체재인 **LoLI-Street**이 규모(33k쌍 > 5,650쌍)·장면 적합성(거리 특화)·배포 접근성(Kaggle) 모두에서 우위이므로 실질적 손실은 없다.
> 유일한 공백은 LSRW의 **스마트폰(화웨이) 촬영분 2,480쌍**이 주는 "타깃 기기 센서 특성" 근접성인데, 이는 **자체 야간 촬영 쌍**으로 대체 보완한다 (규모·촬영 지침은 → 2-1).

> **추천 조합**: **LoLI-Street 을 1순위**로 사용. 거리 장면·대규모·접근성 3박자를 만족. LOL은 벤치마크 비교용으로 병행하고, 스마트폰 센서 도메인은 자체 촬영분으로 보완. (LSRW는 위 사유로 후보에서 제외)

### 2-1. 자체 야간 촬영 쌍(paired) 데이터 — 규모·촬영 지침

LSRW 제외로 생긴 "타깃 기기(스마트폰) 센서 도메인" 공백을 자체 촬영으로 보완한다. 단, **paired 촬영은 탐지용 촬영보다 제약이 크므로 규모 목표를 낮게 잡는다.**

#### 목표 규모: **수십~수백 쌍 (평가·미세조정 전용)**
- ❌ **학습 주력으로 쓰지 않는다** — 톤매핑 본학습은 LoLI-Street(33k쌍)이 담당.
- ✅ **용도 1 (우선) — 평가셋**: 자체 촬영 스마트폰 야간 영상에서 LoLI-Street 학습 모델이 실제로 동작하는지 검증. 도메인 갭 측정이 목적이라 **수십 쌍이면 충분**.
- ✅ **용도 2 (여유 시) — 미세조정**: 수백 쌍 확보 시 마지막 단계 파인튜닝에 투입해 센서 특성 보정.

#### 촬영 제약 (탐지용 촬영과 다른 점)
| 제약 | 내용 | 대응 |
|------|------|------|
| **정합(alignment)** | 저조도↔정상 두 장이 **픽셀 단위로 같은 장면**이어야 함 | 삼각대 고정 필수. 손각대 불가 |
| **동적 객체 배제** | 보행자·차량이 지나가면 두 장의 내용이 달라져 **쌍이 깨짐** | 인적 드문 시간대·장소 선택, 촬영 후 육안 검수로 폐기 |
| **노출만 변경** | ISO/조리개가 아닌 **노출시간(셔터)** 만 바꿔 쌍 생성 | 스마트폰 프로/수동 모드 사용 (자동 모드 불가) |
| **장면 다양성** | 소규모라 장면 편중 시 평가 신뢰도 하락 | 계단·인도·횡단보도·가로등 유무 등 **유형별 균등 배분** |

> **주의**: 이 제약(삼각대·정지 장면) 때문에 paired 데이터는 **③단계 탐지용 야간 촬영과 별도 세션**으로 진행해야 한다. 탐지용은 손에 들고 걸으며 동적 장면을 찍는 것이 오히려 바람직하므로 촬영 방식이 상충한다. 팀원3의 촬영 일정에 **두 종류를 분리해 계상**할 것.

## 3. 추가 추천 — 야간 객체탐지(③단계)

| 데이터셋 | 구성 | 적합성 | 비고 |
|----------|------|--------|------|
| **BDD100K (night subset)** | 10만 클립 중 약 20%가 야간, 10개 클래스(보행자·신호등 등) | △ 보행자·구조물 라벨 풍부하나 **차량 시점** | 대규모 사전학습 보조용 |

> BDD100K는 규모가 커 사전학습 가중치로 유용하나, 차량 시점 편향이 있으므로 **보행 시점 데이터로 반드시 파인튜닝** 전제. DarkFace는 우선순위 낮음(선택).

## 4. 추가 추천 — 계단·단차 탐지 (기존 데이터셋의 최대 공백)

기획서의 핵심 위험 요소인 **계단**은 위 야간 데이터셋 어디에도 클래스가 없음 → 별도 확보가 반드시 필요.

| 데이터셋 | 구성 | 적합성 | 비고 |
|----------|------|--------|------|
| **StairNet / Ultra-fast Stair Detection** | 단안 RGB 기반 계단선(convex/concave) 검출, 학습 2,670 / 검증 424장 | ✅ **단안 카메라** 기반이라 프로젝트 입력부와 일치 | 실시간 성능 우수, 라벨은 계단선 형태. ⚠️ **데이터셋만 [Mendeley](https://data.mendeley.com/datasets/3jjdm6rn96/1) 공개, 코드·사전학습 가중치는 미공개** (2026-07 확인) |
| **RGB-D Stair Dataset** | 학습 4,776 / 검증 1,216장(RGB+Depth), convex/concave 라벨 | △ 정밀하나 **Depth 포함** | 단안 프로젝트엔 RGB만 활용 |

> **주의**: 대부분 계단 데이터가 **주간·실내** 위주 → 야간 성능을 위해 자체 야간 계단 촬영 데이터(팀원3 담당)로 파인튜닝하거나, ②단계 저조도 개선을 거친 뒤 탐지하는 순서 설계가 중요.

### 4-1. 계단 처리 방식 검토 — "라벨링 최소화" 전략

계단을 **딥러닝으로 대량 라벨링해야만 하는가?** → **아니오.** 계단은 *평행한 수평 엣지의 반복*이라는 강한 구조적 사전정보가 있어, 라벨링 부담을 줄이는 두 가지 접근을 **모두 후보로 채택**한다.

> 순수 고전 CV 단독은 야간에서 재현율이 불안정(약한 엣지·눈부심 오탐·혼동 객체·상행/하행 구분 곤란)하고, 계단은 **낙상 위험의 안전 크리티컬 요소**라 놓치면 안 됨 → 아래 두 방식을 병행/보강 구조로 설계.

#### 후보 ① 하이브리드 (고전 CV + 기하 검증) — 라벨링 거의 불필요
```
②저조도 개선 → 고전 CV로 계단 후보(Canny→Hough 평행 수평선 군집) 제안 → 기하 규칙/소형 분류기로 검증
```
- **핵심**: ②단계 저조도 개선을 **먼저** 통과시키면 엣지가 살아나 고전 CV 성능이 크게 개선됨 (파이프라인 순서상 공짜로 얻는 이점).
- **검증 규칙(라벨링 불요)**: 선 간격의 규칙성 · 선 개수 · 소실점 수렴 여부로 오탐(횡단보도·보도블록 줄눈·난간 등) 필터링.
- **장점**: 연산 저렴 → 15FPS 온디바이스 목표에 유리, 자체 라벨링 부담 최소.
- **한계**: 원근·부분 가림에 약함, 상행/하행 판별 보조 규칙 필요.

#### 후보 ② 사전학습 모델 파인튜닝 (StairNet) — 라벨링 소량
- **StairNet** 등 계단선(convex/concave) 검출로 이미 학습된 단안 RGB 모델을 가져와 **자체 야간 소량 데이터만 파인튜닝**.
- **장점**: 밑바닥 대량 라벨링 회피, 비정형 상황(원근·가림)에 고전 CV보다 강건.
- **한계**: 사전학습 데이터가 주간·실내 위주 → 야간 도메인 갭 보정 필요.

> ⚠️ **전제 변경 (2026-07-26 확인)**: 후보 ②는 "공개된 사전학습 가중치를 받아 소량 파인튜닝"을 전제로 했으나, **StairNet은 코드·가중치 저장소가 공개되지 않았고 [Mendeley](https://data.mendeley.com/datasets/3jjdm6rn96/1)에 데이터셋(2,670/424장)만 공개**되어 있음. 즉 후보 ②는 실제로는 *파인튜닝*이 아니라 **밑바닥 학습**이 되며, 그 데이터마저 주간·실내 위주라 야간 도메인 갭까지 함께 떠안게 됨 → 보강책의 비용이 원안보다 크게 상승. 아래 대응 선택지로 재설계.

#### 후보 ② 재검토 — 대응 선택지

| 안 | 내용 | 라벨링 부담 | 추론 예산 | 리스크 |
|----|------|-------------|-----------|--------|
| **(a) 하이브리드 강화** | 후보 ①에 무게를 싣고, 검증 단계의 **소형 이진 분류기(계단/비계단)** 만 자체 야간 데이터로 학습 | 낮음 (패치 단위 이진 라벨 — BBox보다 훨씬 가벼움) | 낮음 | 원근·가림 취약성은 여전히 후보 ①의 한계를 승계 |
| **(b) YOLO 클래스 통합** ★ | StairNet 아키텍처 재구현 대신 **보행자 탐지 YOLO에 `stairs` 클래스를 추가**해 단일 모델로 통합 | 중간 (야간 계단 BBox 자체 라벨링) | **낮음 — 모델 1개로 통합** | 계단선(convex/concave) 단위가 아닌 영역 단위 검출이라 상행/하행 구분은 별도 규칙 필요 |
| **(c) StairNet 직접 학습** | Mendeley 데이터로 StairNet 계열을 밑바닥부터 학습 | 낮음 (공개 라벨 사용) | 높음 (탐지 모델 2개 동시 구동) | 구현·학습 비용 최대, 주간·실내 도메인 갭 보정 부담 |

**권장: (b)** — 어차피 야간 계단은 자체 촬영 데이터로 파인튜닝해야 하므로 "사전학습 가중치 확보"의 이점이 사라진 상황. 그렇다면 별도 모델을 하나 더 구동하는 것보다 **탐지 모델 하나에 클래스를 얹는 편이 15FPS 예산과 파이프라인 단순화 양쪽에 유리**함. (a)는 (b)와 배타적이지 않으므로 후보 ①의 오탐 필터 개선용으로 병행 가능.

#### 채택 방침 (①·② 병행)
- **1차**: 후보 ① 하이브리드를 기본 파이프라인에 탑재 (경량·라벨링 무부담).
- **보강**: 재현율/오탐이 목표 미달 시 **(b) YOLO `stairs` 클래스 통합**으로 대체·앙상블. 오탐 위주 문제라면 (a) 소형 이진 분류기를 먼저 투입.
- **(c)는 보류**: (b)가 목표 재현율에 미달하고 계단선 단위의 정밀 검출(상행/하행 판별 포함)이 필수로 판명될 때만 검토.
- **발표 포지셔닝**: "계단은 구조적 사전정보 기반 고전 CV+기하 검증, 보행자 등 비정형 객체는 딥러닝"의 **task-adaptive 설계**로 어필. 보행자·비정형 장애물은 고전 CV로 불가 → **딥러닝 파이프라인은 그대로 유지**됨.

## 5. ★ 최우선 추천 — AI Hub 「인도(人道) 보행 영상」 (국내·보행 시점·장애물)

프로젝트 목표에 **가장 근접**한 국내 공개 데이터셋. 시각장애인·고령자의 보행 안전을 위해 구축되어 목적 자체가 일치.

- **시점**: 1인칭 보행자 시점(도로·인도, 실내외) — 차량 시점 문제 해소.
- **어노테이션**:
  - 장애물 검출: 충돌 위험 객체 **29종** BBox/폴리곤 (사람·자동차·가로수·볼라드·가로등 등)
  - 노면(Surface) 마스킹: 재질·손상 등 노면 객체 **20종** — 단차·계단 관련 노면 위험 포함 가능
  - Depth 예측: 스테레오 캘리브레이션 제공
- **적합성**: ✅✅✅ **보행 시점 + 장애물 + 국내 환경(간판·표지 등)** 3박자 부합. 프로젝트가 겨냥한 실사용 환경과 가장 유사.
- **한계**: 대부분 **주간 촬영** → 야간 파인튜닝 또는 저조도 합성 증강 필요. 라이선스·이용 신청(AI Hub 회원가입·승인) 절차 확인 필요.
- 링크: https://aihub.or.kr/aihubdata/data/view.do?dataSetSn=189

> **활용 전략**: AI Hub 인도보행 데이터로 **보행 시점 객체·노면**을 학습 → NightOwls/ExDark로 **야간 강건성** 보강 → 자체 야간 계단·보행자 촬영본으로 최종 파인튜닝. 주간 인도보행 이미지에 ②단계 저조도 개선 모델의 역변환(저조도 합성)을 적용해 야간 학습 데이터를 증강하는 방법도 유효.

## 6. 데이터 수집 가능 여부 및 라이선스 (2026-07 기준)

**결론: 데이터 확보는 병목이 아님.** 대부분 오늘 즉시 착수 가능하며, AI Hub만 한국 휴대폰 본인인증이 전제.

| 데이터셋 | 지금 가능? | 절차 | 상업 이용 |
|----------|-----------|------|-----------|
| **ExDark** | ✅ 즉시 | GitHub 공개 다운로드 | BSD-3, **비상업 자유 / 상업은 저자 문의**(cs.chan@um.edu.my) |
| **LoLI-Street** | ✅ 즉시 | 공개(ACCV 2024) — Kaggle·Google Drive | 연구용 |
| **LOL / SID** | ✅ 즉시 | GitHub·공개 링크 | 연구용 공개 (상업 조건 개별 확인 필요) |
| **LSRW** | ⛔ 미사용 | **Baidu Pan 전용 배포** → 중국 계정·클라이언트 필요, 국내 전송 속도 문제로 제외 (2장 참고) | — |
| **StairNet 등 계단** | ✅ 즉시 | **Mendeley 공개 — 데이터셋만** (코드·가중치 없음) | 연구용 |
| **NightOwls** | ⚠️ 등록 후 | 사이트 다운로드(연구용 승인 즉시) | ❌ **비상업 전용 — 상업 이용 불가** |
| **AI Hub 인도보행** | ⚠️ 인증 후 | **한국 휴대폰 본인인증** → 신청 → 자동승인 → 다운로드 | AI Hub 이용정책 확인 필요 |

### ⚠️ 라이선스 상업성 리스크
해커톤 **프로토타입·연구·시연 단계는 전부 사용 가능**. 단, 기획서의 **구독형 앱(상업 모델)** 관점에서 상용화 단계에는 재검토 필요:
- **NightOwls**: 비상업 전용 → 상용 제품 학습엔 불가. 상용 시 **자체 야간 보행자 데이터로 대체** 필요.
- **ExDark**: 상업 이용은 저자 별도 문의.
- **AI Hub**: 개방데이터라 영리 이용 가능한 경우가 많으나 데이터별 조건 상이 → 이용정책 확인.

> 자체 촬영 데이터(팀원3)는 라이선스 제약이 없어, 상용화 대비 **자체 데이터 비중을 높이는 것**이 안전.

### 착수 순서
1. **오늘 바로**: ExDark + LoLI-Street(+LOL) 다운로드 → ②저조도 개선·③탐지 베이스라인 착수
2. **오늘~내일**: NightOwls 등록(연구용, 승인 즉시) → 보행자 사전학습
3. **한국 휴대폰 보유 시 오늘**: AI Hub 인도보행 인증·신청(자동승인) → 보행 시점 데이터
4. **병행**: 자체 야간 계단·보행자 촬영 시작

### 2단 학습 구성 (기획서 근거 보강)
1. **사전학습**: NightOwls + ExDark + AI Hub 인도보행(주간) → 야간·보행 시점의 광범위한 표현 학습
2. **파인튜닝**: 자체 촬영 야간 계단·보행자 소규모 데이터 → 저조도 실효 성능 확보
