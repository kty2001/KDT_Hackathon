## 1. 왜 이 규칙인가 — 한 문단

야맹증 보행자에게 필요한 건 **멀리서 미리 아는 것**이다. 발밑에 와서 알려주면 늦다.
그런데 지금 `stairs` 는 **멀리 있는 계단을 찾는 능력이 한 번도 측정된 적이 없다** —
학습 소스인 StairNet 이 *계단이 화면을 채운 사진*이라 그런 표본이 아예 없기 때문이다.
**자체 촬영분이 그 공백을 메우는 유일한 기회이고, 라벨 규칙이 그걸 살리거나 죽인다.**

---

## 2. 박스 치는 법

### 2-1. 계단 전체를 1박스

```
   ✅ 이렇게                        ❌ 이렇게 아님
   ┌───────────────┐               ┌───────────────┐
   │ ┌───────────┐ │               │ ┌───────────┐ │  ← 단마다 박스
   │ │▔▔▔▔▔▔▔▔▔▔▔│ │               │ ├───────────┤ │
   │ │▔▔▔▔▔▔▔▔▔▔▔│ │               │ ├───────────┤ │
   │ │▔▔▔▔▔▔▔▔▔▔▔│ │               │ ├───────────┤ │
   │ └───────────┘ │               │ └───────────┘ │
   └───────────────┘               └───────────────┘
```

단마다 치면 안 되는 이유는 학습보다 **④ 강조 렌더** 쪽이 크다. 계단 단마다 박스를 그리면
저시력 사용자 화면이 **가로줄로 덮인다.** 잔존시력을 가리지 않는 것이 ④의 설계 원칙인데
정면으로 위반한다. 보행 보조에 필요한 신호는 "여기 계단이 있다" 하나다.

**박스 범위**: 계단의 **디딤판·챌판이 이루는 면 전체**. 난간·벽은 포함하지 않는다.
맨 윗단 뒤쪽 바닥과 맨 아랫단 앞쪽 바닥은 계단이 아니므로 뺀다.

### 2-2. 한 프레임에 계단이 둘 이상이면 — **각각 1박스**

⚠️ **이 항목만은 StairNet 에 답이 없다.** StairNet 은 이미지당 박스가 정확히 1개인데,
그건 원본의 성질이 아니라 `stairnet_to_bbox.py` 가 선분을 전부 하나로 합쳐서 그렇다.

**규칙**: 사람이 보기에 **끊어진 별개의 계단이면 따로**, 층계참(중간 평평한 곳)으로
이어진 한 계단이면 **묶어서 하나**로 친다. 판단이 갈리면 6장에 적는다.

### 2-3. 잘림·가림 — 보이는 부분까지만

화면 밖으로 잘렸거나 사람·기둥에 가려졌으면 **보이는 부분에만** 박스를 친다.
가려진 뒤쪽을 추정해서 넓히지 않는다.

이것이 StairNet 의 실제 방식이다 — 박스의 **76.3%가 화면 경계에 닿아 있고 42.5%는
좌우로 관통**한다. 잘리면 잘린 대로 친다.

```
  화면 밖으로 잘린 계단              사람이 가린 계단
  ┌───────────────┐               ┌───────────────┐
 ─┼───────────┐   │               │ ┌────┐  ┌───┐ │  ← 가려진 구간은
 ▔│▔▔▔▔▔▔▔▔▔▔▔│   │               │ │▔▔▔▔│🚶│▔▔▔│ │     비우고 양쪽만
 ▔│▔▔▔▔▔▔▔▔▔▔▔│   │               │ └────┘  └───┘ │     ...이 아니라
 ─┼───────────┘   │               │               │     ↓
  └───────────────┘               │ ┌───────────┐ │  ← 가린 것이 계단
   보이는 만큼만 박스                │ │▔▔▔🚶▔▔▔▔▔▔│ │     '안'에 있으면
                                  │ └───────────┘ │     하나로 감싼다
                                  └───────────────┘
```

> **구분**: 계단을 **가로막고 선 사람**은 계단 박스 안에 들어와도 된다 (계단은 그 뒤로
> 이어지므로 하나로 감싼다). 계단을 **둘로 갈라 놓을 만큼 큰 가림**(건물 모서리 등)이면
> 2-2 에 따라 별개로 친다.

## 3. ★ 최소 크기 — 하한을 두지 않는다

### 왜 StairNet 을 따를 수 없나

"StairNet 을 최대한 따른다"가 이 항목만은 적용되지 않는다. 따라갈 대상이 없어서다.

| StairNet 실측 (train 2,670장) | |
|---|---|
| 박스 높이 **32px 미만** | **0.0%** |
| 프레임 대비 면적 중앙값 | **47.5%** |
| 면적 5% 미만 | 2.1% |

작은 계단을 **"라벨하지 않기로 한 것"이 아니라, 그런 사진이 애초에 없다.**
StairNet 은 계단 앞에 서서 찍은 사진 모음이라 계단이 늘 화면을 채운다.
따라서 최소 크기에 관해 StairNet 은 **아무 말도 하지 않는다.**

### 하한을 두면 무슨 일이 생기나

이 프로젝트에서 **이미 한 번 겪은 실패**다.

> NightOwls `ignore`-only 프레임 3,097장 — **사람이 있는데 라벨이 비어 있어
> "사람=배경"을 가르쳤다.** 그래서 학습에서 제외했다 (→ STATUS 3장 함정 4).

멀리 있는 계단을 라벨하지 않으면 똑같이 **"계단=배경"을 가르친다.** 게다가 평가에서도
GT 가 없으니 못 찾아도 감점이 없어, **"거리 계단을 못 찾는다"는 사실 자체가 보이지 않는다.**
STATUS 2장 4번의 미결 질문 — 오탐 0.2%가 *"헛보지 않는다"* 인지 *"거리 장면에선 아예
발화하지 않는다"* 인지 — 가 영원히 안 갈린다.

### 그래서

**크기 하한 없음.** 몇 픽셀이든 계단으로 판단되면 박스를 친다.

작은 박스가 학습을 흔들 걱정은 `ignore` 로 처리한다 (아래 4장). 실제로 탐지가 되는지는
별개 문제이고 — YOLO 는 작은 물체에 원래 약하다 — **그건 라벨이 있어야 측정할 수 있다.**

## 4. `ignore` — 지우는 대신 표시한다

**계단인지 아닌지 육안으로 확신이 안 서면** 박스를 빼지 말고 `ignore` 로 표시한다.

| | 학습 | 평가 |
|---|---|---|
| `stairs` 박스 | 양성으로 학습 | 못 찾으면 감점 |
| **`ignore` 박스** | **손실에서 제외** (배경으로도 안 가르침) | **감점 없음** |
| 라벨 없음 | 배경으로 학습 ⚠️ | 찾으면 오탐 ⚠️ |

`ignore` 를 쓸 상황:

- 너무 멀거나 어두워 계단인지 턱인지 갈리지 않는 것
- 모션블러로 뭉개진 것
- 계단이긴 한데 유리·반사에 비친 상(실물이 아닌 것)

> NightOwls 가 같은 방식을 쓰고 `scripts/nightowls_yolo.py` 에 처리 경로가 이미 있다.
> 자체 촬영분도 같은 규약으로 두면 두 소스를 그대로 섞을 수 있다.
>
> **라벨 툴에서의 표기**: 별도 클래스 `ignore` 로 두고 변환 단계에서 거른다.
> 클래스 id 는 데이터셋 빌드 때 정하므로 라벨러는 이름만 맞추면 된다.

## 5. 무엇을 `stairs` 로 볼 것인가 — StairNet 기준

StairNet 을 따르되, 자체 촬영에서만 나오는 경계 사례가 있다.

| 대상 | 판정 | 비고 |
|---|---|---|
| 2단 이상의 계단 | ✅ `stairs` | 기본 |
| **1단짜리 턱·단차** | ⚠️ `ignore` | StairNet 에 표본이 없다. 보행 위험은 크지만 별개 판단이 필요 |
| 경사로(램프) | ❌ 라벨 안 함 | 계단이 아니다 |
| 에스컬레이터 | ⚠️ `ignore` | 계단 형태지만 움직인다 |
| 계단 모양 조형물·화단 단 | ❌ 라벨 안 함 | 보행로가 아니다 |
| 내려가는 계단 | ✅ `stairs` | **놓치기 쉽다** — 위에서 보면 바닥과 구분이 어렵다. 야맹증 보행에서 가장 위험한 대상이므로 특히 챙길 것 |

> ⚠️ **StairNet 라벨 자체의 한계** — 육안 검수 결과, 원본이 *보이는 계단 전부가 아니라
> 일부 단만* 라벨한 경우가 있다 (→ data.md 4-5). **자체 촬영분은 이걸 따라하지 말고
> 보이는 계단 전체를 감싼다.** "StairNet 을 따른다"는 *계단의 정의*에 대한 것이지
> *원본의 라벨 누락*까지 따르라는 뜻이 아니다.

## 7. 라벨링 끝나고 — 검수

같은 자로 재서 StairNet 과 비교한다.

```powershell
uv run python scripts/label_stats.py --labels outputs/datasets/<자체촬영>/labels/train
```

**볼 것 두 개**:

| 지표 | StairNet | 자체 촬영분이 이러면 |
|---|---|---|
| 경계 접촉률 | 76.3% | 크게 낮으면 → 잘린 계단을 안 쳤거나 추정해서 넓혔다 (2-3 위반) |
| **높이 32px 미만 비율** | **0.0%** | **여전히 0 에 가까우면 → 거리 계단이 안 담겼다** |

두 번째가 핵심이다. 0 이 나오면 라벨링이 아니라 **촬영**이 문제일 수 있다 —
계단에 가까이 붙어서만 찍었다는 뜻이므로, `C2` 에 **멀리서 접근하는 구간**을
추가로 찍어야 한다. **`C5` 평가셋을 확정하기 전에 확인할 것.**
