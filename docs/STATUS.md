## 1. 단계별 현재 상태

### ★ 아키텍처 확정 — 표시/탐지 경로 분리 (8/2, `C7`)

```
프레임 ─┬─→ [탐지 경로] 원본 그대로 ────────→ ③ YOLO ──┐
        │                                              ↓
        └─→ [표시 경로] ② D1A1+bf(+ts) ──────→ ④ 경계선 강조 → 화면
```

②를 탐지 앞단에 두면 mAP 가 내려가고, 무엇보다 **`stairs` 야간 오탐이 0.1% → 5.7%
로 되살아난다**(`C4b` 가 0 으로 만든 결함이 전처리 한 번에 복귀). 그래서 **탐지는 원본을
먹는다.** 분리는 비용이 아니라 이득이다 — 두 경로가 독립이라 병렬화 가능하고 ②의 지연이
③에 더해지지 않는다 (→ [detection.md 7장](detection.md)).

| 단계 | 채택안 | 확정된 수치 | 상태 |
|------|--------|-------------|------|
| ① 눈부심 억제 | `D1`(Drago) 하이라이트 압축 — **②에 흡수 예정** | 광원 코어 250→157 @640×360 | 🗣️ 통합 여부 회의 안건 |

## 2. 지금 막혀 있는 것 — 우선순위

1. 🔴 **`C2` 자체 야간 촬영** — `C3`→`C5`→`C7`→`C8`→`C9` 가 전부 직렬로 매달려 있다.
   **선행: 🗣️ 회의 안건 3·4** (촬영 프로토콜·초상권 / `stairs` BBox 라벨 정의).
   라벨 정의를 사후에 바꾸면 **전량 재라벨링**이라 촬영 전에 못 박아야 한다.
2. 🔴 **`P3` 앱 껍데기** — 구현 0건. `C9` 통합 시점에 없으면 통합할 곳이 없다.
3. ⚠️ **② 속도 게이트** — 720p 를 확실히 통과하는 건 `A1`·`A2`(6ms) 뿐인데 **이 둘은
   글레어 축 실격**이다. 채택안 `D1A1+bf+ts` 는 640×360 환산 **≈20.4ms** 로 게이트
   경계선(판정 불가 밴드 15~25ms). `bf` 를 A3 시간축으로 대체하려던 카드는 **8/2 에
   기각**됐다 (→ lowlight_classical 8장). 남은 수: 내부 해상도 하향 · 셰이더 이식 ·
   `C11` 실기기 재판정.
   - ✅ **다만 표시/탐지 분리로 압박이 줄었다** — ②의 지연이 ③에 더해지지 않으므로
     두 경로를 병렬로 돌리면 예산 계산이 달라진다. 🗣️ 회의 안건 1에 반영할 것.
4. **`stairs` — 저조도는 문제가 아니고 *도메인*이 문제다** (8/2 실측).
   StairNet 야간 76장에서 mAP50 **0.993** · recall 0.987 로 **주간보다도 높다.**
   그러나 StairNet 은 *계단이 화면을 채운 사진*이라, **보행 중 멀리 있는 계단**은
   측정 자체가 불가능하다. 야간 거리 오탐 0.2% 는 conf 스윕(0.25→0.01 에서도 6.1%,
   최대 conf 0.396)으로 **"헛보지 않는다" 쪽에 가깝다**고 봤지만, rec 34 엔 진짜 계단이
   없어 **"거리 장면에선 아예 발화하지 않는다"** 를 배제하지 못한다 — `C2` 자체 촬영이
   유일한 판별 수단이다 (→ [detection.md 8장](detection.md)).
5. **일반 장애물(볼라드·전봇대 등)은 클래스 자체가 없다.** `person`·`stairs` 둘뿐.
   유일한 후보 **AIHub 인도보행을 샘플 실측**(8/3)했다 — 장애물 29종 있으나
   **계단 없음·야간 없음** (주간 전용). 🗣️ 추가 여부는 회의 안건이며, 추가하는 경우의
   진행 경로(29종+`stairs` 스키마 · person ID 통일 · `C4c` 회귀 게이트 · 부분
   다운로드)는 [data.md 3-1](data.md) 에 확정해 뒀다. **회의 결정 전 착수 금지.**

## 3. ⚠️ 반복해서 발목을 잡은 함정 — 작업 전 반드시 확인

1. **개발 val 은 야간 실효 성능을 못 본다.** `C4b` 에서 실야간이 5.4배 좋아지는 동안
   개발 val 은 0.892 → 0.892 로 **한 자리도 안 움직였다.** 판정은 **항상**
   held-out(NightOwls rec 34) 또는 자체 촬영분(`C5`)에서 한다.
2. **지표를 영상 통계에 상대적으로 정의하지 말 것.** 백분위·평균 대비로 정의하면
   영상이 바뀔 때 *재는 대상 자체*가 달라진다. 노이즈·글레어·대비 3개 지표가 전부
   이 결함으로 육안과 어긋났다 (→ `scripts/metrics.py`).
3. **이 PC 는 15~25ms 를 판정할 수 없다.** 프로세스 간 10~20% 흔들린다.
   다른 작업(학습 등)과 동시에 재면 **1.7배까지 부풀어 오른다.**
4. **NightOwls `ignore`-only 프레임 3,097장은 학습에 넣지 말 것.** 사람이 있는데
   라벨이 비어 있어 "사람=배경"을 가르친다 (→ `scripts/nightowls_yolo.py`).
5. **NightOwls rec 34·38 은 학습 금지.** 34 는 판정용 held-out, 38 은 ② 시간축 전용.
   `build_detect_dataset.py` 가 실행을 거부하도록 막아 뒀다.
6. **Windows 에서 `--cache ram` 금지.** worker 가 spawn 이라 캐시가 복제돼 죽는다.
7. **Raw 데이터 수정 금지.** 산출물은 전부 `outputs/`(git 비추적), 이미지는 하드링크.
8. **ultralytics 의 AutoUpdate 를 켜 둔 채 ONNX 추론을 돌리지 말 것** (8/3 실측).
   `onnxruntime`(CPU) 이 없으면 **제멋대로 설치**해 `uv.lock` 밖 패키지를 끼워 넣는다.
   이 프로젝트는 `onnxruntime-gpu` 를 쓰는데 **둘은 같은 디렉토리를 공유**해서, 나중에
   CPU 판을 지우면 공용 파일까지 사라져 `onnxruntime` 이 통째로 망가진다
   (`module has no attribute 'InferenceSession'`). 복구는 `uv sync --reinstall-package
   onnxruntime-gpu`. 예방은 임포트 전 `YOLO_AUTOINSTALL=false` (→ `scripts/export_onnx.py`).
9. **`.pt` 와 ONNX 를 같은 이미지로 비교할 때 파일 경로를 그대로 넘기지 말 것** (8/3).
   ultralytics 는 `.pt` 에 **가변 rect 레터박스**(16:9 → 640×384), 고정 shape ONNX 에는
   640×640 을 먹인다. 입력 해상도가 달라 비정사각 이미지에서 신뢰도가 0.1 씩 벌어지는데
   이는 **변환 손실이 아니라 전처리 차이**다. 미리 정사각 레터박스한 배열을 양쪽에
   똑같이 넣으면 좌표 오차 0.0001px 로 일치한다.
